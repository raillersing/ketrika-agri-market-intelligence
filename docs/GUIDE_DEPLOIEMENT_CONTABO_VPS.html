Production · Guide Officiel

Déploiement VPS Contabo

Plateforme Ketrika Agri Market Intelligence — Ubuntu 24.04 / 22.04 LTS

0 Pré-requis nécessaires

Avant d'entamer l'installation sur votre VPS Contabo, rassemblez les informations suivantes :

  • Adresse IPv4 publique Contabo : Reçue par email (ex: 161.97.xxx.xxx).
  • Accès SSH root : Mot de passe ou clé SSH configuré lors de la commande.
  • Nom de domaine / Sous-domaine : Par exemple market.votre-domaine.com avec un enregistrement DNS de type A pointant vers l'IP du VPS.
  • Terminal : PowerShell sur Windows, ou Terminal sur macOS/Linux.
Note : Si vous n'avez pas encore configuré de nom de domaine, la section 7 vous explique comment tester immédiatement avec l'adresse IP brute.

1 Connexion SSH et Amorçage du VPS

Ouvrez votre terminal et connectez-vous au serveur en tant que root :

ssh root@<IP_DE_VOTRE_VPS_CONTABO>

Une fois connecté, exécutez le script d'amorçage conçu pour automatiser la sécurisation du serveur et l'installation de Docker :

curl -fsSL https://raw.githubusercontent.com/ketrika/ai-agent/main/deploy/bootstrap-vps.sh -o bootstrap.sh
chmod +x bootstrap.sh
./bootstrap.sh

Ce que fait ce script automatiquement :

  • Mise à jour complète du système (apt upgrade).
  • Création d'un utilisateur sécurisé nommé deploy.
  • Installation de Docker Engine et du plugin Docker Compose officiel.
  • Activation du pare-feu UFW (seuls les ports 22, 80 et 443 sont ouverts).
  • Protection anti-bruteforce Fail2ban et mises à jour de sécurité automatiques.
  • Préparation du répertoire applicatif /opt/ketrika.

2 Bascule sur l'utilisateur deploy

Pour des raisons strictes de sécurité, nous n'exécutons jamais l'application sous root :

su - deploy
cd /opt/ketrika

3 Récupération du code source

Clonez le dépôt dans le répertoire de travail :

git clone https://github.com/ketrika/ai-agent.git .

4 Configuration des variables d'environnement (.env)

Créez le fichier .env à partir du modèle de configuration :

cp .env.example .env
chmod 600 .env

Générez des mots de passe aléatoires et robustes directement dans la console :

# Mot de passe sécurisé pour PostgreSQL :
openssl rand -hex 24

# Clé secrète pour les tokens JWT d'authentification :
openssl rand -hex 32

Ouvrez ensuite le fichier pour l'éditer avec nano :

nano .env

Remplissez les variables clés :

# Configuration générale
APP_ENV=prod
DOMAIN=market.votre-domaine.com
ACME_EMAIL=votre-email@domaine.com

# Base de données PostgreSQL + PostGIS
POSTGRES_USER=ketrika
POSTGRES_PASSWORD=<COLLEZ_LE_MOT_DE_PASSE_POSTGRES_GENERE>
POSTGRES_DB=ketrika
DATABASE_URL=postgresql+psycopg://ketrika:<COLLEZ_LE_MOT_DE_PASSE_POSTGRES_GENERE>@db:5432/ketrika
COPILOT_DB_PASSWORD=<MOT_DE_PASSE_LECTURE_SEULE>

# Stockage Bronze S3 (MinIO autonome sur le VPS)
S3_ENDPOINT_URL=http://minio:9000
S3_ACCESS_KEY=minioadmin
S3_SECRET_KEY=minioadmin
S3_BUCKET_BRONZE=bronze
S3_REGION=auto

# Sécurité des sessions
JWT_SECRET=<COLLEZ_LA_CLE_JWT_GENEREE>
CORS_ORIGINS=https://market.votre-domaine.com

# Intelligence Artificielle (Mode Replay pour tests)
LLM_PROVIDER=replay
EXTERNAL_SEND_ENABLED=0

Sauvegardez avec Ctrl + O, confirmez avec Entrée, puis quittez avec Ctrl + X.

5 Lancement et Initialisation des Données

1. Construction des conteneurs de production

docker compose -f docker-compose.prod.yml build

2. Démarrage de la base de données PostGIS

docker compose -f docker-compose.prod.yml up -d db

Attendez quelques secondes et vérifiez que la base est prête (état healthy) :

docker compose -f docker-compose.prod.yml ps db

3. Application des migrations de schéma Alembic

docker compose -f docker-compose.prod.yml run --rm api alembic upgrade head

4. Chargement initial des référentiels vivriers (Seed)

Cette commande peuple les régions/districts de Madagascar, les produits vivriers PPN (riz, maïs, manioc, huile, etc.) et les sources déclarées :

docker compose -f docker-compose.prod.yml run --rm api python -m ketrika.normalize.loader seed

5. Démarrage complet de tous les services

docker compose -f docker-compose.prod.yml up -d

Vérifiez que tous les services sont en ligne :

docker compose -f docker-compose.prod.yml ps

Vous devez observer les conteneurs : caddy, web, api, db, dagster-webserver et dagster-daemon en cours d'exécution.

6 Accès et Vérifications

1. Tester l'API en ligne

curl -I https://market.votre-domaine.com/v1/health

Vous recevez un statut 200 OK avec "database": "connected".

2. Documentation Swagger interactive

Rendez-vous dans votre navigateur sur :
https://market.votre-domaine.com/docs

3. Tableau de bord Web

Ouvrez votre domaine principal :
https://market.votre-domaine.com

4. Accéder à l'orchestrateur Dagster via tunnel SSH sécurisé

L'interface de gestion des pipelines n'est pas exposée publiquement par sécurité. Pour y accéder depuis votre machine personnelle :

ssh -L 3001:localhost:3001 deploy@<IP_DE_VOTRE_VPS_CONTABO>

Puis ouvrez dans votre navigateur local : http://localhost:3001.

7 Variante : Tester immédiatement sans nom de domaine

Si vous n'avez pas de domaine disponible tout de suite, vous pouvez configurer Caddy pour écouter directement sur le port 80 de l'IP publique.

1. Éditez deploy/Caddyfile et remplacez la ligne {$DOMAIN:localhost} { par :

:80 {
	encode zstd gzip

	handle /v1/* {
		reverse_proxy api:8000
	}
	handle /docs* {
		reverse_proxy api:8000
	}
	handle /openapi.json {
		reverse_proxy api:8000
	}
	handle {
		reverse_proxy web:3000
	}
}

2. Dans .env, indiquez DOMAIN=http://<IP_DE_VOTRE_VPS>.

3. Redémarrez le reverse-proxy :

docker compose -f docker-compose.prod.yml restart caddy

Accédez ensuite directement à http://<IP_DE_VOTRE_VPS>.
