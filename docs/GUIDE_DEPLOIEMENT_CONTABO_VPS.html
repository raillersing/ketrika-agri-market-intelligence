Ketrika Agri Market Intelligence Guide Production

Déploiement VPS Contabo

Guide pas-à-pas interactif pour déployer l'infrastructure complète de Ketrika Agri Market Intelligence sur un serveur Cloud VPS Contabo (Ubuntu 24.04 / 22.04 LTS).

⚙️ Personnalisation dynamique des commandes

Saisissez vos paramètres réels ci-dessous. Toutes les commandes du tutoriel se mettront à jour en direct !

0

Spécifications recommandées du VPS Contabo

Pour faire tourner la stack complète (PostGIS, MinIO S3, FastAPI, Next.js, Dagster, Caddy), l'offre recommandée chez Contabo est :

✓ Offre : Cloud VPS S ou Cloud VPS M
✓ CPU : 4 vCPU cores (minimum 2 vCPU)
✓ RAM : 8 Go (ou 16 Go pour confort)
✓ Disque : 50 Go NVMe ou SSD
✓ OS : Ubuntu 24.04 LTS (Noble Numbat)
✓ Réseau : 1 adresse IPv4 publique dédiée
💡 Conseil Contabo : Lors de votre commande sur le portail Contabo, sélectionnez Ubuntu 24.04. Vous pouvez coller votre clé publique SSH (id_ed25519.pub) dans la section Cloud-Init pour une connexion sécurisée sans mot de passe.
1

Configuration du Nom de Domaine (DNS)

Avant d'activer le certificat HTTPS Let's Encrypt automatique, configurez votre nom de domaine chez votre registrar (Cloudflare, Namecheap, OVH, etc.) :

Type d'enregistrement Nom / Hôte Valeur cible (IP Contabo) TTL / Proxy
A market 161.97.100.50 Automatique (DNS Only si Cloudflare)

Vérifiez la propagation DNS depuis votre terminal local :

dig +short market.ketrika.mg

La commande doit renvoyer exactement votre adresse IP Contabo : 161.97.100.50.

2

Connexion SSH & Amorçage du Serveur (Bootstrap)

1. Connectez-vous au serveur en tant que root depuis votre terminal :

ssh root@161.97.100.50

2. Lancez le script d'amorçage officiel du dépôt. Il installe Docker Engine, UFW, Fail2ban, et prépare l'utilisateur non-root deploy :

curl -fsSL https://raw.githubusercontent.com/raillersing/ketrika-agri-market-intelligence/main/deploy/bootstrap-vps.sh -o bootstrap.sh
chmod +x bootstrap.sh
./bootstrap.sh
🛡️ Sécurité appliquée par le script :
  • Pare-feu UFW activé (seuls les ports 22 (SSH), 80 (HTTP) et 443 (HTTPS) sont autorisés).
  • Protection anti-bruteforce Fail2ban activée contre les attaques SSH.
  • Création de l'utilisateur dédié deploy membre du groupe docker.
  • Répertoire applicatif /opt/ketrika configuré avec les bons droits.
3

Bascule sur l'utilisateur deploy & Clonage

Ne déployez jamais l'application sous l'utilisateur root. Basculez sur l'utilisateur deploy :

su - deploy
cd /opt/ketrika

Clonez le dépôt officiel sur la branche principale main :

git clone https://github.com/raillersing/ketrika-agri-market-intelligence.git .
4

Configuration des Secrets de Production (.env)

1. Copiez le template de configuration et verrouillez ses permissions :

cp .env.example .env
chmod 600 .env

2. Générez des mots de passe cryptographiques sécurisés avec openssl :

# Mot de passe robuste pour PostgreSQL :
openssl rand -hex 24

# Clé secrète pour les tokens JWT d'authentification :
openssl rand -hex 32

# Mot de passe lecture-seule pour le Copilote SQL :
openssl rand -hex 24

3. Ouvrez le fichier .env avec nano :

nano .env

Adaptez les variables clés avec vos valeurs :

APP_ENV=prod
DOMAIN=market.ketrika.mg
ACME_EMAIL=admin@ketrika.mg

# Base de données PostgreSQL + PostGIS 17
POSTGRES_USER=ketrika
POSTGRES_PASSWORD=<COLLEZ_VOTRE_MOT_DE_PASSE_POSTGRES_24HEX>
POSTGRES_DB=ketrika
DATABASE_URL=postgresql+psycopg://ketrika:<COLLEZ_VOTRE_MOT_DE_PASSE_POSTGRES_24HEX>@db:5432/ketrika
COPILOT_DB_PASSWORD=<COLLEZ_VOTRE_MOT_DE_PASSE_COPILOT_24HEX>

# Stockage Bronze S3 (MinIO ou Cloudflare R2)
S3_ENDPOINT_URL=http://minio:9000
S3_ACCESS_KEY=qualification-admin
S3_SECRET_KEY=<MOT_DE_PASSE_MINIO_OU_R2>
S3_BUCKET_BRONZE=bronze
S3_REGION=auto

# Sécurité & Tokens JWT
JWT_SECRET=<COLLEZ_VOTRE_CLE_JWT_32HEX>
CORS_ORIGINS=https://market.ketrika.mg

# IA & Copilote (Gemini ou Replay local)
LLM_PROVIDER=replay
GEMINI_API_KEY=
EXTERNAL_SEND_ENABLED=0

Sauvegardez avec Ctrl + O, confirmez avec Entrée, puis quittez avec Ctrl + X.

5

Construction des Images Docker de Production

Construisez les conteneurs optimisés pour la production (FastAPI Backend, Next.js Frontend, Caddy Reverse Proxy) :

docker compose -f docker-compose.prod.yml build

Cette étape compile le frontend Next.js et installe les dépendances Python dans l'environnement conteneurisé scellé.

6

Initialisation de la Base de Données PostGIS

1. Démarrez le service de base de données PostGIS en arrière-plan :

docker compose -f docker-compose.prod.yml up -d db

2. Attendez que la base soit prête (état healthy) :

docker compose -f docker-compose.prod.yml ps db

3. Appliquez l'ensemble des 21 migrations de schéma Alembic jusqu'à head :

docker compose -f docker-compose.prod.yml run --rm api alembic upgrade head

4. Chargez les référentiels officiels de Madagascar (les 23 régions, 119 districts, taxonomie PPN vivriers) :

docker compose -f docker-compose.prod.yml run --rm api python -m ketrika.normalize.loader seed
7

Démarrage Complet & Certificat SSL Let's Encrypt

Démarrez l'ensemble des services en production :

docker compose -f docker-compose.prod.yml up -d

Vérifiez que tous les conteneurs sont en ligne :

docker compose -f docker-compose.prod.yml ps

Inspectez les logs de Caddy pour confirmer l'obtention automatique du certificat TLS/HTTPS Let's Encrypt :

docker compose -f docker-compose.prod.yml logs caddy | grep -i "certificate"
🔒 HTTPS Automatique : Caddy contacte automatiquement Let's Encrypt via le protocole ACME, valide le challenge HTTP-01 sur le port 80, et génère un certificat SSL/TLS valide avec renouvellement automatique.

9

Accès Sécurisé à l'Orchestrateur Dagster (Tunnel SSH)

Par principe strict de sécurité, l'interface de gestion des pipelines Dagster (port 3001) n'est pas exposée publiquement sur Internet.

Pour y accéder en toute sécurité depuis votre machine locale, créez un tunnel SSH chiffré :

# À exécuter depuis votre ordinateur personnel (PowerShell ou Terminal local) :
ssh -L 3001:localhost:3001 deploy@161.97.100.50

Puis ouvrez dans votre navigateur local : http://localhost:3001 pour administrer les déclencheurs de collecte.

10

Sauvegardes Automatiques Quotidiennes (Cron)

Configurez une tâche Cron quotidienne pour sauvegarder la base de données PostgreSQL chaque nuit à 02h00 :

crontab -e

Ajoutez la ligne suivante à la fin du fichier :

0 2 * * * cd /opt/ketrika && ./deploy/backup.sh >> /var/log/ketrika-backup.log 2>&1

Les sauvegardes seront archivées sous /opt/ketrika/backups/ avec compression et empreinte SHA-256 de vérification.
