Guide de Déploiement : Irooa Ketrika sur Serveur Contabo

Procédure pas-à-pas pour déployer l'application Irooa Ketrika sur votre VPS Contabo, sous le nom de domaine irooa.store, tout en garantissant la cohabitation 100 % étanche avec l'autre application déjà hébergée sur la machine.

Serveur Cible
VPS Contabo (Linux Ubuntu)
Nom de Domaine
irooa.store / www.irooa.store
Contrainte Majeure
Autre application déjà active (Zéro Conflit)
Certificat SSL
Let's Encrypt (HTTPS Automatique)
0 Architecture de Cohabitation : Comment éviter les conflits ?

Sur un serveur qui héberge déjà une application, les ports web standards 80 (HTTP) et 443 (HTTPS) sont généralement déjà occupés par un serveur web maître (le plus souvent Nginx ou Apache).

Règle d'or : Ne JAMAIS forcer un nouveau conteneur Docker à écouter sur 80:80 ou 443:443 directement sur l'hôte, sous peine de planter les deux applications avec l'erreur « bind: address already in use ».

La solution propre et professionnelle :

  • Irooa Ketrika tourne dans ses propres conteneurs Docker isolés et expose son frontend uniquement en local sur le port 127.0.0.1:3005 et son API sur 127.0.0.1:8090.
  • La base de données PostgreSQL reste confinée dans le réseau Docker interne (aucun conflit avec un PostgreSQL ou MySQL existant sur le port 5432).
  • Le Nginx hôte du serveur Contabo joue le rôle de chef d'orchestre : selon le nom de domaine demandé, il redirige les requêtes de façon transparente :
    • votre-autre-app.com ➔ redirigé vers votre ancienne application.
    • irooa.store ➔ redirigé vers Irooa Ketrika (port 3005).
1 Diagnostic du Serveur Contabo (Audit des Ports Actifs)

Connectez-vous en SSH à votre serveur Contabo depuis votre terminal : 

ssh root@VOTRE_IP_CONTABO

Vérifiez quels services et ports sont actuellement occupés sur votre serveur :

ss -tulpn | grep -E ':(80|443|3000|3005|5432|8000|8090)'

Vérifiez quel serveur web gère actuellement le port 80/443 :

systemctl status nginx || systemctl status apache2
Astuce RAM Contabo (Swap obligatoire) : Les VPS Contabo disposent souvent de 4 à 8 Go de RAM. Pour éviter tout crash lors de la compilation de Next.js ou de l'exécution des modèles de machine learning, assurez-vous d'avoir 4 Go de mémoire Swap active : 
# Vérifier si le Swap existe déjà
swapon --show

# Si vide, créer un Swapfile de 4 Go en 3 commandes :
fallocate -l 4G /swapfile
chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
2 Configuration DNS de votre Domaine irooa.store

Chez votre registraire de domaine (Cloudflare, Namecheap, Hostinger, GoDaddy, etc.), accédez à la gestion de la Zone DNS de irooa.store et ajoutez ces deux enregistrements :

Type Nom / Hôte Valeur / Cible TTL Description
A @ (racine) VOTRE_IP_CONTABO Auto / 300s Pointe irooa.store vers votre serveur
A (ou CNAME) www VOTRE_IP_CONTABO Auto / 300s Pointe www.irooa.store vers votre serveur

Vérifiez que le domaine pointe bien vers votre serveur (depuis votre machine ou le serveur) :

dig +short irooa.store

(La commande doit renvoyer l'adresse IP publique exacte de votre VPS Contabo).

3 Installation du Projet sur le Serveur Contabo

Assurez-vous que Docker et Docker Compose sont installés sur le serveur Contabo : 

docker --version && docker compose version

Si Docker n'est pas installé : curl -fsSL https://get.docker.com | sh

Créez le dossier d'hébergement et clonez le dépôt Git :

mkdir -p /var/www
cd /var/www
git clone https://github.com/raillersing/ketrika-agri-market-intelligence.git irooa-ketrika
cd irooa-ketrika
4 Configuration Docker Dédiée Contabo (Sans Conflit de Ports)

Nous allons créer un fichier docker-compose.contabo.yml qui isole les ports et évite tout conflit avec l'autre application : 

cat << 'EOF' > docker-compose.contabo.yml
services:
  db:
    image: postgis/postgis:17-3.5
    restart: unless-stopped
    environment:
      POSTGRES_USER: ${POSTGRES_USER:-ketrika}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: ${POSTGRES_DB:-ketrika}
    volumes:
      - irooa_pgdata:/var/lib/postgresql/data
      - ./docker/db/init.sql:/docker-entrypoint-initdb.d/01-init.sql:ro
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U $${POSTGRES_USER:-ketrika} -d $${POSTGRES_DB:-ketrika}"]
      interval: 10s
      timeout: 5s
      retries: 5

  minio:
    image: minio/minio:RELEASE.2025-02-07T23-21-09Z
    restart: unless-stopped
    command: ["server", "/data", "--console-address", ":9001"]
    environment:
      MINIO_ROOT_USER: ${MINIO_ROOT_USER:-admin}
      MINIO_ROOT_PASSWORD: ${MINIO_ROOT_PASSWORD}
    volumes:
      - irooa_miniodata:/data
    ports:
      # Accessible en local uniquement si besoin de déboguer
      - "127.0.0.1:9100:9000"
      - "127.0.0.1:9101:9001"

  api:
    image: ketrika-backend:prod
    build:
      context: ./backend
      dockerfile: Dockerfile
    restart: unless-stopped
    environment:
      - APP_ENV=prod
      - BOOTSTRAP_DEMO_ADMIN=false
      - DATABASE_URL=postgresql+psycopg://${POSTGRES_USER:-ketrika}:${POSTGRES_PASSWORD}@db:5432/${POSTGRES_DB:-ketrika}
      - POSTGRES_USER=${POSTGRES_USER:-ketrika}
      - POSTGRES_PASSWORD=${POSTGRES_PASSWORD}
      - POSTGRES_DB=${POSTGRES_DB:-ketrika}
      - S3_ENDPOINT_URL=http://minio:9000
      - S3_ACCESS_KEY=${MINIO_ROOT_USER:-admin}
      - S3_SECRET_KEY=${MINIO_ROOT_PASSWORD}
      - S3_BUCKET_BRONZE=bronze
      - S3_REGION=us-east-1
      - JWT_SECRET=${JWT_SECRET}
      - COPILOT_DB_PASSWORD=${COPILOT_DB_PASSWORD}
      - CORS_ORIGINS=https://irooa.store,https://www.irooa.store
      - PYTHONPATH=/app/src
      - KETRIKA_REPO_ROOT=/workspace
    volumes:
      - ./:/workspace:ro
    ports:
      # L'API FastAPI écoute en local uniquement sur 8090
      - "127.0.0.1:8090:8000"
    depends_on:
      db:
        condition: service_healthy

  web:
    image: ketrika-web:prod
    build:
      context: ./web
      dockerfile: Dockerfile
    restart: unless-stopped
    environment:
      - NEXT_PUBLIC_API_BASE_URL=/api/v1
      - API_INTERNAL_URL=http://api:8000
      - PORT=3000
      - HOSTNAME=0.0.0.0
    ports:
      # Le Frontend Next.js écoute en local uniquement sur 3005
      - "127.0.0.1:3005:3000"
    depends_on:
      api:
        condition: service_healthy

volumes:
  irooa_pgdata:
  irooa_miniodata:

networks:
  default:
    name: irooa-net
EOF

Générez un fichier .env.production sécurisé avec des mots de passe aléatoires forts :

# Génération des secrets aléatoires
cat << EOF > .env
POSTGRES_USER=ketrika
POSTGRES_PASSWORD=$(openssl rand -hex 16)
POSTGRES_DB=ketrika
MINIO_ROOT_USER=irooa_admin
MINIO_ROOT_PASSWORD=$(openssl rand -hex 16)
JWT_SECRET=$(openssl rand -hex 32)
COPILOT_DB_PASSWORD=$(openssl rand -hex 16)
DOMAIN=irooa.store
EOF

# Protéger le fichier d'environnement
chmod 600 .env
5 Configuration du Nginx Hôte (Le Reverse Proxy Central)

Nous configurons Nginx sur votre VPS pour rediriger le trafic de irooa.store vers le port 3005 d'Irooa Ketrika, sans toucher à la configuration de votre autre application. 

cat << 'EOF' > /etc/nginx/sites-available/irooa.store
server {
    listen 80;
    listen [::]:80;
    server_name irooa.store www.irooa.store;

    client_max_body_size 50M;

    # En-têtes de sécurité
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

    # Redirection vers le frontend Next.js d'Irooa
    location / {
        proxy_pass http://127.0.0.1:3005;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;

        # Timeouts pour les calculs de prédiction ML (12 mois)
        proxy_connect_timeout 60s;
        proxy_send_timeout 120s;
        proxy_read_timeout 120s;
    }
}
EOF

Activez le site et testez la syntaxe de configuration Nginx :

# Création du lien symbolique
ln -s /etc/nginx/sites-available/irooa.store /etc/nginx/sites-enabled/

# Tester qu'aucune syntaxe n'est cassée pour toutes vos applications
nginx -t

# Si le test est 'successful', recharger Nginx sans coupure
systemctl reload nginx
6 Activation du HTTPS Gratuit avec Certbot (Let's Encrypt)

Générez le certificat SSL officiel pour irooa.store et www.irooa.store. Certbot va automatiquement mettre à jour la configuration Nginx avec HTTPS : 

# Installer Certbot si nécessaire
apt-get update && apt-get install -y certbot python3-certbot-nginx

# Obtenir le certificat SSL automatique
certbot --nginx -d irooa.store -d www.irooa.store --non-interactive --agree-tos -m contact@irooa.store --redirect
✅ Renouvellement automatique : Let's Encrypt renouvelle le certificat automatiquement tous les 60 jours via le timer systemd de Certbot.
7 Lancement des Conteneurs et Initialisation des Données

Retournez dans le dossier du projet et démarrez la stack Irooa Ketrika en arrière-plan : 

cd /var/www/irooa-ketrika

# Construire et lancer tous les conteneurs
docker compose -f docker-compose.contabo.yml up -d --build

# Vérifier que tous les conteneurs sont 'healthy' et en marche
docker compose -f docker-compose.contabo.yml ps

Créez votre utilisateur administrateur de production :

docker compose -f docker-compose.contabo.yml exec api python -c "
from ketrika.core.db import get_db_session
from ketrika.core.models.db import UserAccount
from ketrika.api.auth import hash_password
from uuid import uuid4

with get_db_session() as session:
    admin = UserAccount(
        user_id=uuid4(),
        email='admin@irooa.store',
        password_hash=hash_password('VOTRE_MOT_DE_PASSE_SECURISE'),
        role='admin',
        disabled=False
    )
    session.add(admin)
    session.commit()
    print('Administrateur admin@irooa.store créé avec succès !')
"
